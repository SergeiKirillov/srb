Формат vCard 3.0 описывается стандартом RFC 2426 (и синтаксически базируется на RFC 2425). Каждая строка имеет структуру:

[ГРУППА.]ИМЯ_ПОЛЯ[;ПАРАМЕТР=ЗНАЧЕНИЕ...]:ЗНАЧЕНИЕ

Ниже приведена полная спецификация стандартных полей (свойств), обязательных и опциональных, а также их параметров.

## 1. Служебные и обязательные поля

| Поле | Обязательно | Описание и формат значения                                    | Пример |
| -------- | ---------------------- | ------------------------------------------------------------------------------------ | ------------ |
| BEGIN    | Да                   | Всегда имеет значение VCARD. Открывает карточку. | BEGIN:VCARD  |
| VERSION| Да | Версия стандарта. Для 3.0 должно идти сразу после  BEGIN. | VERSION:3.0 | 
| FN | Да | Formatted Name — полное отображаемое имя (одна строка). | FN:Иван Петрович Сидоров | 
| N | Да | Name — структурированное имя. 5 компонентов через ;: Фамилия;Имя;Отчество(второе имя);Префикс;Суффикс. | N:Сидоров;Иван;Петрович;г-н;к.т.н.|
|END| Да| Всегда имеет значение VCARD. Закрывает карточку.| END:VCARD|

## 2. Идентификация и внешний вид

| Поле| Описание и формат значения| Пример|
| --- | --- | --- |
| NICKNAME| Псевдоним или никнейм. Несколько значений разделяются запятой. | NICKNAME:Vanya,Admin | 
| PHOTO| Фотография контакта. Задается либо через VALUE=URI, либо встраивается в Base64 (ENCODING=b;TYPE=JPEG).|PHOTO;ENCODING=b;TYPE=JPEG:/9j/4AAQ...|
| BDAY | Дата рождения в формате ISO 8601 (YYYY-MM-DD или YYYYMMDD, реже с временем YYYY-MM-DDTHH:MM:SSZ).| BDAY:1985-04-123. |

## Адреса и геолокация

| Поле| Описание и формат значения| Пример| 
| --- | --- | --- |
| ADR| Address — структурированный почтовый адрес. 7 компонентов через ;:  Почтовый ящик;Доп. адрес (офис/кв);Улица и дом;Город;Регион/Область;Индекс;Страна| ADR;TYPE=WORK,PREF:;;ул. Ленина, д. 10, оф. 5;Караганда;;100000;Казахстан|

|GEO| Географические координаты в формате широта;долгота (десятичные градусы). | GEO:49.8047;73.1094| 
|TZ| Часовой пояс (смещение от UTC или название зоны).| TZ:+05:00|

| Поле | Описание и формат значения | Пример |
|---|---|---|
| TITLE | Должность или функциональная обязанность.| TITLE:Главный инженер | 
| ROLE | Роль или профессия (по классификации, например, по стандарту ISO).| ROLE:Проектировщик|

## Нестандартные расширения (X-)
Стандарт разрешает любые пользовательские поля, начинающиеся с префикса X-. Современные адресные книги (Google Contacts, Apple, Android, Thunderbird) активно используют их для соцсетей, мессенджеров и связанных лиц:

- X-SOCIALPROFILE;TYPE=telegram:[https://t.me/username](https://t.me/username)
- X-JABBER:user@jabber.org / X-SKYPE:username
- X-ABLabel:... (специфичные метки Apple для группировки полей вида item1.TEL + item1.X-ABLabel:Рабочий 2)
- X-ANNIVERSARY:2010-06-15 (годовщина)

## Параметры полей и правила синтаксиса
Параметры указываются после имени поля через точку с запятой (;):
1. TYPE — уточняет назначение поля (значения перечисляются через запятую):
    - Для TEL: HOME (домашний), WORK (рабочий), CELL (мобильный), VOICE (голосовой), FAX (факс), MSG (голосовая почта), PAGER, PREF (основной/предпочтительный).
    - Для ADR и LABEL: DOM (внутренний), INTL (международный), POSTAL, PARCEL, HOME, WORK, PREF.
    - Для EMAIL: INTERNET (по умолчанию), X400, PREF.
    - Для PHOTO / LOGO: формат изображения (JPEG, PNG, GIF).
2. ENCODING — кодировка бинарных данных. В версии 3.0 используется только ENCODING=b (Base64). Примечание: QUOTED-PRINTABLE, популярный в vCard 2.1, в версии 3.0 запрещен — весь текст должен быть в UTF-8.
3. VALUE — переопределяет тип данных (например, VALUE=URI, VALUE=DATE, VALUE=TEXT).
4. LANGUAGE — язык значения (например, FN;LANGUAGE=ru:Иван Сидоров).

Важные правила форматирования:
- Кодировка: UTF-8 (указывается в заголовках файла/потока, в самом теле CHARSET=UTF-8 не пишется, в отличие от vCard 2.1).- Перенос строк (Folding): строки длиннее 75 байт должны разбиваться переносом CRLF (\r\n) с обязательным пробелом или табуляцией в начале следующей строки.
- Экранирование: символы ,, ;, \ и перевод строки внутри значений экранируются обратным слешем (\,, \;, \\, \n). Исключение — разделители компонентов в составных полях (N, ADR, ORG).
